## 当前挖掘模式：无约束扫描

本项目为**无约束扫描**，与启发式扫描隔离。

### 定位
依赖模型自身能力，专注挖掘**前台**可利用漏洞。不注入权重文件，不依赖启发式扫描的定权与队列。

### 本轮注入
系统仅注入侦察阶段的 `docs/code-map.md` 与 `docs/auth.md`，不注入权重文件或 FileWeight 数据。
`FinishFile` 工具可用。系统不按权重分配焦点文件；模型自主选择要分析的文件。

### 漏洞收录范围
参考赏金模式：只提交 RCE、SSTI、反序列化、SQL 注入、XML 注入、任意文件操作（读/写/删/改/复制/解压穿越等）、能打内网的 SSRF、敏感信息泄露、文件上传、文件包含、目录遍历、认证绕过、越权、DoS、存储型 XSS、1-click CSRF、有服务端机密危害的源码硬编码密钥，以及其他确定能造成实际危害的问题。

**不提交**：CORS / 反射 XSS / DOM XSS / 缺速率限制 / 安全头 / 普通 CSRF（仅缺 token / 低危状态变更）/ 开放重定向 / 弱随机等低危害项。

### 单轮结束标准
1. 产出 **RCE 漏洞**（`vuln_type` 为 `rce` 或 `command_injection`）：立即提交并触发超时总结结束本轮。
2. 触发**超时总结**（系统自动注入超时摘要模板）：本轮结束。

### 阶段结束标准
产出**任意 RCE 漏洞**（`vuln_type` 为 `rce` 或 `command_injection`）后，阶段结束。
发现其他类型前台漏洞也需提交，但不作为阶段结束条件。

### 与启发式扫描的关系
本阶段与启发式扫描隔离——不共享文件队列、不注入 FileWeight 数据、不继承已审文件列表。
可以同时运行，但独立记录进度。

### 其他规则
- SubmitVuln / MarkFalsePositive / SearchOldVuln 等工具均可用，规则同赏金模式。
- 靶场动态验证 / 局部验证同赏金模式：Reviewer 负责环境搭建与 PoC 收口。
- config_premise、root_cause_key、同根因只交一份等闸门同样适用。
- poc.py 要求同赏金模式：有 HTTP 面时 CLI 参数化（`-u/--url` / `--proxy` / `-c/--cmd`）。
