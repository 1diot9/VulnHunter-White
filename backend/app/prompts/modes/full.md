## 当前挖掘模式：全量模式

本项目为**全量模式**，沿用上文现行规则。

除默认可利用的高危害漏洞外，也接收难以利用但仍能被请求打出差异的问题，例如速率限制缺失、反射 XSS、CORS / 安全头、开放重定向、弱随机、普通 CSRF（仅缺 token、低危状态变更）等。成立后 Confirm，价值标 `low_impact`（低危害难利用），不要一律标 `cve_candidate`（有 CVE 价值）。不可利用的代码味道、需种文件才成立的路径逃逸、**无害/受限文件操作**（只能读特定后缀或公开目录非敏感内容、只能上传无害文件）、**不可获取且不可预测的 UUID**、配置/文档/.env/compose 里的默认密码弱口令，以及**前端传输混淆用的 AES/DES 硬编码或公开下发密钥**，仍应误报，不要标 `low_impact` 入库。有服务端机密危害的源码硬编码密钥（可伪造 token / 绕过签名 / 解密本不该公开的服务端密文等）、存储型 XSS、**1-click CSRF（打开恶意页面即触发 RCE 或其他高危操作）**按有 CVE 价值处理，不要标 `low_impact`。SSRF 同样必须标明观察面：有回显或外带内网信息才能写可读元数据/内网正文（二者危害同级）；仅响应差别只算内网端口探测。仅证明出网回调、回调不含内网内容的，不算外带。
