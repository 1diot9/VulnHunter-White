## 当前挖掘模式：赏金模式（覆盖上文冲突条款）

本项目为**赏金模式**。若与上文「低危害难利用仍可 Confirm / `low_impact` 入库」冲突，**以本节为准**。

### 接收类型
只提交、只确认能造成实际危害的问题：RCE、SSTI、反序列化、SQL 注入、XML 注入、任意文件操作（读/写/删/改/复制/解压穿越等）、能打内网的 SSRF、敏感信息泄露、文件上传、文件包含、目录遍历、认证绕过、越权、DoS、**存储型 XSS**、**有服务端机密危害的源码硬编码密钥**、以及其他**确定能造成实际危害**的漏洞。

存储型 XSS 用 `stored_xss` 提交，且须持久化后在**其他用户**浏览器执行（可盗会话 / 代操作）。不要把反射 XSS、DOM XSS、仅自己触发的 Self-XSS 写成存储型。存储型 XSS 价值标 `cve_candidate`，不要标 `low_impact`。

源码硬编码密钥用 `hardcoded_secret` 提交：仅限编译进程序、且被当作**服务端机密**的常量。合格例子：JWT/HMAC 签名密钥、接口签名 secret、私钥、第三方 API Key、用于保护库内/备份等本不应对未授权方公开的服务端加解密密钥。知道密钥后须能造成未授权危害（伪造 token、绕过签名校验、冒用第三方凭据、解密攻击者本不该看到的服务端密文）。价值标 `cve_candidate`。配置文件、`.env`、compose、文档、安装向导里用户可改的口令/密钥不要提交。

以下**不算**硬编码密钥漏洞（误报，不要标 `cve_candidate`）：仅用于前端传输混淆的 AES/DES（密钥写在前端 JS，或故意通过公开接口下发给前端）；前后端同钥且设计上对所有客户端公开，危害只是「解开本就会在前端解开的字段」或「解开已拦截的登录包」。AES 提高抓包改包成本 ≠ 机密性边界；不要把「密钥硬编码 + 公开下发」本身当成 CVE。

反射 XSS / DOM XSS 不要提交；已提交的应 `MarkFalsePositive`，不要 Confirm。

`other` 仅当能证明实际危害（代码执行、敏感数据泄露、越权读写删、任意文件操作等）。不要用 `other` 收留 CORS、反射 XSS、缺速率限制、安全头。

### 明确丢弃（误报，不要标低危害难利用）
以下即使请求本身能打出差异，赏金模式也**直接误报**，不要 Confirm、不要标 `low_impact`：
- CORS / ACAO 反射、缺失 CSP / X-Frame-Options 等安全头
- 开放重定向（除非能明确升级为鉴权劫持、token 盗取等实际危害）
- 反射 XSS、DOM XSS、Self-XSS
- 速率限制缺失、单点限速绕过、验证码可爆破但无进一步危害
- 弱随机 / 可预测 token（除非能直接导致认证绕过）
- 配置文件 / `.env` / compose / 文档里的默认账号口令或用户可修改密钥
- 前端传输混淆用的 AES/DES 硬编码或公开下发密钥（见上文）
- 纯配置加固建议、信息性扫描项

SSRF 必须能打到内网、云元数据或本机敏感口；只能打公网、无内网/凭据危害的不要提交。提交与确认必须标明观察面：**有回显**（响应含目标正文）或 **仅响应差别**（用状态码/时延/报错探测内网端口）。两者都算「能打内网」，但仅差别探测不得写成已获取云元数据凭据；未证明回显却声称可读元数据的，Reviewer 按探测面改报告后 Confirm，不要按凭据窃取确认，也不要为此打回 Worker。

### 利用前提
必须在**默认配置**，或**只修改应用自身提供的配置选项**下可利用。提交时用 `config_premise` 标明：`default`（默认配置）或 `specific`（须改应用自身配置）。**特定配置不包括**官方文档已明确警示会导致安全风险的配置；仅在这类已警示开关下才成立的不要提交。
允许：改 `application.yml` / 后台功能开关 / 官方文档列出的应用配置项（且文档未把它标成已知风险开关）。
若项目开启动态验证：Reviewer 在独立环境轮用 Docker 搭建/复用靶场（`env/`、`docs/lab.md`）。靶场 = 默认部署的运行实例，不是「为了让洞成立」而改过的利用环境。
局部验证模式不搭靶场，由 Reviewer 用沙箱 harness 做函数级复现，成立性门槛不变。
禁止：往磁盘种 payload 或模板、上传主题、摆放非默认目录文件、改非应用配置的依赖版本、组合第二个独立漏洞才打得通。
不要把本节理解成「不要 docker / 不要搭靶场 / 不要写 env.json」。开启靶场动态时 Docker 靶场要搭；禁止的是在靶场里制造利用条件。未开启动态验证时 Reviewer 只做静态审核。
