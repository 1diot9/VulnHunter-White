## 当前挖掘模式：赏金模式（覆盖上文冲突条款）

本项目为**赏金模式**。若与上文「低危害难利用仍可 Confirm / `low_impact` 入库」冲突，**以本节为准**。

### 接收类型
只提交、只确认能造成实际危害的问题：RCE、SSTI、反序列化、SQL 注入、XML 注入、任意文件操作（读/写/删/改/复制/解压穿越等）、能打内网的 SSRF、敏感信息泄露、文件上传、文件包含、目录遍历、认证绕过、越权、DoS、以及其他**确定能造成实际危害**的漏洞。

XSS（含反射 XSS / 存储 XSS / DOM XSS）不要提交；已提交的应 `ReturnToWorker(false_positive=true)`，不要 Confirm。

`other` 仅当能证明实际危害（代码执行、敏感数据泄露、越权读写删、任意文件操作等）。不要用 `other` 收留 CORS、XSS、缺速率限制、安全头。

### 明确丢弃（误报，不要标低危害难利用）
以下即使请求本身能打出差异，赏金模式也**直接误报**，不要 Confirm、不要标 `low_impact`：
- CORS / ACAO 反射、缺失 CSP / X-Frame-Options 等安全头
- 开放重定向（除非能明确升级为鉴权劫持、token 盗取等实际危害）
- 反射 XSS、存储 XSS、DOM XSS
- 速率限制缺失、单点限速绕过、验证码可爆破但无进一步危害
- 弱随机 / 可预测 token（除非能直接导致认证绕过）
- 纯配置加固建议、信息性扫描项

SSRF 必须能打到内网、云元数据或本机敏感口；只能打公网、无内网/凭据危害的不要提交。

### 利用前提
必须在**默认配置**，或**只修改应用自身提供的配置选项**下可利用。
允许：改 `application.yml` / 后台功能开关 / 官方文档列出的应用配置项。
允许且必须：Reviewer 在独立环境轮用 Docker 搭建/复用靶场（`env/`、`docs/lab.md`）。靶场 = 默认部署的运行实例，不是「为了让洞成立」而改过的利用环境。
禁止：往磁盘种 payload 或模板、上传主题、摆放非默认目录文件、改非应用配置的依赖版本、组合第二个独立漏洞才打得通。
不要把本节理解成「不要 docker / 不要搭靶场 / 不要写 env.json」。Docker 靶场要搭；禁止的是在靶场里制造利用条件。
