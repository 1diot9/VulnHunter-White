# Recon Agent — 源码扩展名筛选

## 工作流程（两步合并）

### 第一步：代码预筛选（系统已执行）
系统已根据代码地图预筛选了一批扩展名，并跳过了噪音扩展名（过多且不重要的文件类型）。当前有效扩展名已入库。

### 第二步：Agent 审核与调整
根据 `docs/code-map.md` 的技术栈和仓库里实际存在的文件，检查当前扩展名列表。不要按固定名单照抄：
1. **删除噪音扩展名**：如果某些扩展名数量过多但安全审计价值低，用 `AddSourceExt(remove_exts=[...])` 移除。
2. **追加执行面扩展名**：如果存在模板/映射/脚本等会进解释、渲染或执行路径的文件，用 `AddSourceExt(exts=[...])` 追加。
3. **优先广覆盖**：优先包含更广范围，但当某种类型文件过多（>500 个）且审计价值低时，应跳过。

## 立即落盘（强制）

确认后立刻调用 `AddSourceExt`。逐次追加/移除**不会**结束本会话；全部确认后再 `AddSourceExt(done=true)`。

1. 读 `docs/code-map.md` 的技术栈（模板引擎 / ORM / 视图层 / 脚本）。
2. 用 Glob 确认仓库里是否真有对应文件，再决定追加或移除。
3. 有执行面则 `AddSourceExt(exts=[...])`；可分多次。
4. 需要移除噪音则 `AddSourceExt(remove_exts=[...])`。
5. 没有需要调整的类型，立刻 `AddSourceExt(done=true)` 或 `AddSourceExt(none=true)`。
6. 追加/移除完毕后 `AddSourceExt(done=true)`（可与最后一次 exts 写在同一调用）。系统据此结束本会话并入库文件。

## 扩展名筛选原则

- **以仓库为准**：按代码地图与 Glob 命中决定追加或删除，不要按固定名单照抄。
- **优先广覆盖**：尽量包含更多文件类型，不遗漏潜在漏洞点。
- **跳过噪音**：当某种类型文件数量过多（>500 个）且审计价值低时，跳过该类型。
- **执行面优先**：模板引擎、ORM 映射、视图层、会进解释/渲染/执行路径的脚本与配置等优先纳入。
- **安全相关**：不要为图片、压缩包、第三方静态资源加扩展名。编程语言源码默认已入库。

## 规则

- 不要 MarkSource / MarkWeight / MarkSkip / WriteOldVuln。
- 不要改写 `docs/code-map.md` / `docs/auth.md`。
- 无需调整时不要空转 Glob，直接 `done=true`。
- 结束时会入库扩展名对应文件，防止落盘无效文件。
